## Prerequisites

- **A shadcn project.** Next.js is the reference setup; any framework the shadcn CLI supports
  works the same way, with your own font loading in place of `next/font`.
- **Tailwind CSS v4.** The theme ships its tokens as CSS variables and its patterns as
  `@utility` blocks, which need v4.
- **The `base-nova` style.** The restyled primitives are built on Base UI, so initialise with
  that style (`"style": "base-nova"` in `components.json`). At the interactive prompt pick
  "Base UI", then "Nova"; unattended, the flags are `-b base -p nova` (`-p base-nova` is an
  "Invalid preset"):

  ```bash
  pnpm dlx shadcn@latest init -b base -p nova
  ```

  If your body text renders in a serif after init, `font-sans` points at a variable nothing
  sets: init writes `--font-sans: var(--font-sans);` into `app/globals.css`, while a fresh
  create-next-app layout loads Geist as `--font-geist-sans`. This comes from shadcn's init, not
  from mangacn; rename the variable in `app/layout.tsx` and the body, buttons and labels take
  Geist:

  ```tsx title="app/layout.tsx"
  const geistSans = Geist({ variable: "--font-sans", subsets: ["latin"] });
  ```

- **`cn`.** The `@/lib/utils` helper that `shadcn init` writes.

## Set up

<Steps>
<Step>

### Add the registry

Name the registry in your `components.json`, so `@mangacn/<item>` resolves to the hosted
item files:

```json title="components.json"
{
  "registries": {
    "@mangacn": "https://www.mangacn.com/r/{name}.json"
  }
}
```

Working with an AI agent? [Agents](/docs/agents) sets up shadcn's MCP, the mangacn docs MCP
and the Agent Skill on top of this entry.

</Step>
<Step>

### Install the theme, the fonts, the ink frame and an item

One command takes the theme, the three font items, the ink frame that every drawn component
outlines itself with, and a first item:

<InstallCommand setup />

After that, any item is one `add` away. Keep the ink frame installed before the outlined
items: they import it from `@/components/ink-frame`.

The flags let the line run without a prompt, as an agent or a script runs it. The theme asks
"You are about to install a new theme… Continue?", which only `--yes` answers. And if a stock
or edited file is already there (say `components/ui/button.tsx`, which mangacn's button and
the items built on it replace), the CLI asks to overwrite it; `--overwrite` answers that. Left
unanswered without a terminal, either question ends the run with exit 0 and nothing written.
Every install line on this site carries `--overwrite`, and `--yes` too when the theme is in
the set.

</Step>
<Step>

### Check what landed where

| What | Where |
|---|---|
| Restyled primitives (`button`, `dialog`, …) | `components/ui/<item>.tsx` |
| Manga-native pieces (`speech-bubble`, `panel`, …) | `components/<item>.tsx` |
| Blocks (`chapter-list`, `spread-viewer`) | `components/blocks/<block>/` |
| The ink frame | `components/ink-frame.tsx` |
| Tokens, utilities and keyframes | your `globals.css` |
| Font loaders (`next/font/google`) | your root `layout.tsx` |

Everything is plain source in your project. Edit it as you would your own code.

</Step>
</Steps>

## Without the registry entry

The shadcn CLI also installs straight from the GitHub repository, with no `registries` entry:

```bash
npx shadcn@latest add fldx-dev/mangacn/button --overwrite
```

The same items, by their repository path (`fldx-dev/mangacn/<item>`). Use it to try one item
or when the hosted registry is out of reach.
