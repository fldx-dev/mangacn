For page scans, a cover or an avatar: a dashed ink drop zone with a real file button, a list of the chosen files and a mangacn `progress` per row. It uploads nothing itself: send the files from `onValueChange` and pass each one's `progress` and `status` back to `FileUploadItem`. Put it in a `field` for a label and a description.

There is no WAI-ARIA pattern for file upload; the drop zone is never the only way in:

- the trigger is a `button` that opens the native file dialog through a visually hidden `<input type="file">`, which posts the files with a plain form (`name`);
- the drop zone is a `role="group"` named by its instructions;
- each add and each rejection, with its reason, is announced in a polite live region, and rejected files stay listed with the reason in spot;
- each row's progress is named by the file, and its remove button says "Remove" and the file name.

`labels` holds functions (`remove`, `added`, `rejected`, `size`, `count`), so override them from a client component.
