The `theme` item writes everything on this page into your `globals.css`: CSS variables for
light and dark, Tailwind v4 utilities and keyframes. Change a value there and every item
follows.

## Tokens

Eight tokens carry the whole palette: ink, paper, one spot colour and four screentone greys.
All values are `oklch`.

<TokenSwatches />

| Token | Role |
|---|---|
| `--ink` | line work, text, borders, solid fills |
| `--paper` | page background, card and popover surfaces |
| `--spot` | the single accent: focus ring, destructive, emphasis |
| `--spot-foreground` | text on a spot fill |
| `--tone-1` … `--tone-4` | screentone greys from 10 % to 70 %: hover and muted surfaces, disabled fills, muted text, halftone dots |

Each token is also a Tailwind colour, so `bg-paper`, `text-spot` and `border-ink` work in your
own markup.

### How they map onto shadcn

The theme sets the shadcn semantic variables from the tokens, so a stock component that only
knows `bg-background` still renders ink on paper.

| shadcn variable | Token |
|---|---|
| `--background` / `--foreground` | `--paper` / `--ink` |
| `--card`, `--popover` | `--paper` (the border does the work) |
| `--primary` / `--primary-foreground` | `--ink` / `--paper` |
| `--secondary`, `--muted`, `--accent` | `--tone-1`, with `--ink` text (`--tone-4` for muted text) |
| `--destructive` | `--spot` |
| `--border`, `--input` | `--ink` |
| `--ring` | `--spot` |
| `--chart-1` … `--chart-5` | ink, tone-4, tone-3, tone-2, spot |
| `--sidebar*` | mirrors background, foreground, accent, border and ring |
| `--radius` | `0.125rem`, close to square |

shadcn's `--accent` is a hover surface, so the red is `--spot`, never `--accent`.

## Presets

A preset is the same theme on other paper: it gives the eight tokens other values, in light and
dark, and changes nothing else. The shadcn variables follow through their `var()` references;
the radius, fonts, pen and utilities stay, and there is still exactly one spot colour.

- **Sepia** is an old tankōbon: aged cream paper, brown-black ink and a vermilion spot.
- **Weekly** is the tinted recycled newsprint of a weekly manga magazine: green-grey paper, soft
  black ink and a magenta spot.
- **Blueline** is a pencil draft before inking: cool white paper, blue-black ink and a spot of
  non-photo blue, darkened as far as it must be to read as text.

Pick a look to see this site in it. The choice stays on every docs page in this browser until you

The command installs the chosen look. A preset item brings `theme` by URL, so it works on a fresh
project too. Over an installed theme the CLI writes the same CSS variables again: it overwrites
existing variables in `globals.css` in place whenever a theme is added, and merges the theme's
values first and the preset's over them. You end with one set of tokens, not two. Add
`@mangacn/theme` again to go back to the default.

  </figure>
  <figure className="m-0 grid gap-1 rounded-[var(--radius)] p-4 ink-border">
    <p lang="ja" className="font-dialogue text-xl">遅いぞ。ここで合ってる…？</p>
    <figcaption className="text-sm text-muted-foreground"><code>font-dialogue-ja</code>: Yusei Magic, <code>--font-dialogue-ja</code>. Kana and kanji in the dialogue stack.</figcaption>

</div>

Components use two utilities, `font-display` and `font-dialogue`. The theme's `--font-dialogue`
stack chains the two dialogue faces, so the browser picks per glyph: Latin from Shantell Sans,
Japanese from Yusei Magic. Japanese glyphs are fetched only on pages that use them.

To use your own faces, skip the font items and set `--font-display`, `--font-dialogue-latin` and
`--font-dialogue-ja` yourself.

## Dark mode

Dark mode is the `.dark` class on an ancestor, usually `<html>`, as shadcn and `next-themes` set
it. The night palette is dim, not inverted: paper turns a warm charcoal rather than black, ink
an off-white, and the spot red brightens a little to hold its contrast. Every pair meets
WCAG AA, ink on paper AAA, in both modes.

```css title="globals.css"
.dark {
  --ink: oklch(0.93 0.004 85);
  --paper: oklch(0.24 0.004 60);
  /* … the theme writes the full set */
}
```

### Turn it on

The theme defines `.dark` and nothing else: no `prefers-color-scheme` query. A fresh install
stays light on a dark OS until something sets the class. To follow the OS and offer a toggle,
add [`next-themes`](https://github.com/pacocoursey/next-themes) (`pnpm add next-themes`), as
shadcn does:

```tsx title="components/theme-provider.tsx"
"use client";

import { ThemeProvider as NextThemesProvider } from "next-themes";
import type { ComponentProps } from "react";

export function ThemeProvider(props: ComponentProps<typeof NextThemesProvider>) {
  return <NextThemesProvider {...props} />;
}
```

```tsx title="app/layout.tsx"
import { ThemeProvider } from "@/components/theme-provider";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    // next-themes sets the class before React hydrates, so <html> differs from the server's.
    <html lang="en" suppressHydrationWarning>
      <body>
        <ThemeProvider attribute="class" defaultTheme="system" enableSystem>
          {children}
        </ThemeProvider>
      </body>
    </html>
  );
}
```

`useTheme()` from `next-themes` then reads and sets the mode for a toggle.

Why no media-query fallback in the theme: the items' own `dark:` utilities follow the class
(shadcn writes `@custom-variant dark (&:is(.dark *))`), so a fallback would turn the tokens
dark while those utilities stayed light, and a project that is light on purpose would flip on
a dark OS. One switch, the class, keeps every part of the page in the same mode.

## The pen

Every outline in mangacn is drawn by the ink frame with rough.js, and the pen it draws with is
a set of CSS variables:

| Variable | Default | What it does |
|---|---|---|
| `--outline-width` | `1.5px` | stroke width of every outline |
| `--outline-width-heavy` | `2.1px` | panels and dialogs |
| `--ink-roughness` | `1.2` | how much the line wobbles |
| `--ink-bowing` | `0.8` | how far straight edges bow |
| `--ink-offset` | `1.5` | how far a stroke strays from its corner points |
| `--ink-hachure-gap` | `4px` | gap between hatch lines in hatched fills and shadows |
| `--shadow-offset` | `4px` | shadow distance, only where a component asks for a shadow |

`globals.css`:
