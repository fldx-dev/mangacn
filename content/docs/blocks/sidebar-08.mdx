Stock's inset app shell with a secondary nav, in ink, with stock's six files and exports: one add writes `app/(mangacn-examples)/examples/sidebar-08/page.tsx` and `app-sidebar`, `nav-main`, `nav-projects`, `nav-secondary` and `nav-user` in `components/` (the page as an example route, the components where shadcn's sidebar-08 puts them). Mangacn's [Sidebar](/docs/components/sidebar) in its inset variant draws it all: each section is a link with a chevron that opens its sub-links, support and feedback sit at the sidebar's foot, and it collapses with <kbd>Ctrl</kbd>+<kbd>B</kbd> (<kbd>⌘</kbd>+<kbd>B</kbd> on a Mac) or the trigger and opens as a sheet on phones, beside a volume's blank [panels](/docs/components/panel). It is an alternative to the other sidebar blocks, so adding it replaces their shared files; swap the studio's sample data in `app-sidebar.tsx` for your own.

The page is a server component and the five sidebar files are client components, as in stock's block.

## Props

`AppSidebar` takes the sidebar's own props and the data it draws. Every data prop defaults to the studio's sample, so the page renders as above until you pass your own in `app/(mangacn-examples)/examples/sidebar-08/page.tsx` or your own route. `label` names the navigation landmark (`Studio` by default).

```tsx
<AppSidebar
  label="Workspace"
  brand={brand}
  navMain={sections}
  projects={projects}
  navSecondary={links}
  user={user}
/>
```

The account menu's items (Upgrade to Pro, Account, Billing, Notifications, Log out) do nothing until `userActions` gives them handlers, such as `userActions={{ onLogout }}`; `NavUser` takes the same handlers as props. The page is a server component and cannot pass functions to the client sidebar, so pass `userActions` from a client component of your own that renders `AppSidebar`.
