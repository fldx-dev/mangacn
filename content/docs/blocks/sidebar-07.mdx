Stock's app shell in ink, with stock's six files and exports: one add writes `app/dashboard/page.tsx` and `app-sidebar`, `nav-main`, `nav-projects`, `nav-user` and `team-switcher` in `components/`, where shadcn's sidebar-07 puts them. Mangacn's [Sidebar](/docs/components/sidebar) draws it all, collapsing to icons with <kbd>Ctrl</kbd>+<kbd>B</kbd> (<kbd>⌘</kbd>+<kbd>B</kbd> on a Mac) or the trigger and opening as a sheet on phones, beside a chapter's blank [panels](/docs/components/panel); swap the studio's sample data in `app-sidebar.tsx` for your own.

The page is a server component and the five sidebar files are client components, as in stock's block.

## Props

`AppSidebar` takes the sidebar's own props and the data it draws. Every data prop defaults to the studio's sample, so the page renders as above until you pass your own in `app/dashboard/page.tsx`. `label` names the navigation landmark (`Studio` by default).

```tsx
<AppSidebar
  label="Workspace"
  teams={teams}
  navMain={sections}
  projects={projects}
  user={user}
/>
```

The account menu's items (Upgrade to Pro, Account, Billing, Notifications, Log out) do nothing until `userActions` gives them handlers, such as `userActions={{ onLogout }}`; `NavUser` takes the same handlers as props. The page is a server component and cannot pass functions to the client sidebar, so pass `userActions` from a client component of your own that renders `AppSidebar`.
